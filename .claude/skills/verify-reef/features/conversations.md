# Direct conversations

A user starts a conversation with one Bot, talks to it, comes back to an older conversation and
continues it. Each conversation is its own Space with its own agent session, and the Bot runs with
its default access rules, never a Team's. Contract: `docs/server.md` (Spaces, Bots).

## Sub-features

- `conv-own-session` two conversations with `sam` keep their own sessions: two `session_id`s in `turn`, and the second one's session file never has the first one's codeword.
- `conv-list` `GET /bots/{id}/conversations` lists the Bot's conversations, the one with the newest message first; an unknown Bot is 404.
- `conv-resume` a send to an older conversation, also after a server restart, runs a turn with `--resume <its session id>` and the same `session_id`.
- `conv-access` a conversation's `space_member` row for `sam` has his default `write` (0) while his `team_member` row in `crew` has 1; his `claude` runs with `--disallowedTools Edit,Write,MultiEdit,NotebookEdit` and a Write is refused.
- `conv-memory` `remember` in a conversation defaults to scope `conversation:<its Space id>`; the next conversation's first prompt has no item of it, and `recall` there finds it (`"scope":"conversation:1"`).
- `space-shelves` a free Space's first prompt has `### Space`, `### Project` and `### Your items` only; a conversation's has `### Your items` only.
- `move-link` after `@kit` at the start of a line in a conversation with `sam`, the conversation is read-only (a send is `409`) and `movedTo` links the new Space: a free Space with no Team, `sam` leading and `kit`, each with their default access rules.
- `move-summary` `kit`'s first prompt has the summary `sam` wrote and no line of the conversation's messages.
- `move-mid-line` `@kit` inside a line moves nothing: no new Space, no `movedTo`, `sam` answers as usual.
- `move-action` `POST /spaces/{id}/members` with `kit` on a conversation moves it the same way.
- `window-move` the moved conversation shows a link to the new Space and no message box; "Add Bot" opens a picker without `sam` and moves it too (`$H ui conversation-move`).
- `window-conversations` the sidebar lists the conversations under Conversations, newest first, `+` starts one by picking a Bot, and the phone Spaces tab lists them too (`$H ui conversation`).
- `flow-conversation` a conversation with `sam` is a Space of kind `conversation` with no work item and no Team, and its first turn is `sam`'s (`$H feature work-item-flow conv`).
- `flow-add-bot` `POST /spaces/1/members` with `kit` on that conversation is 202: Space 1 is read-only (a send is 409) and `movedTo` is Space 2, a free Space with no Team where `sam` leads and `kit` is a member, and `kit`'s first turn replays `kit-takeover` (`$H feature work-item-flow conv`). The same script then sends `@kit PROPOSE THE SLOW SEARCH` to Space 2, so that `kit` proposes a Work item (`flow-propose`, `work-items.md`).

## How to get to it (user POV)

- Window: Conversations, `+`, pick a Bot. Click an older row to continue it.
- REST: `POST /spaces {"projectId":1,"name":"...","botId":2,"kind":"conversation"}`, then `/spaces/{id}/send`.

## Gotchas

- `sam` writes the summary in a turn of the conversation, so it is also the conversation's last message, and the string check leaves it out. A conversation that moved refuses every send; its `movedTo` is the link to the new Space.
- A conversation runs in the project folder: it has no work item and so no worktree.
- A conversation started with the default name `<bot> <hh:mm>` is renamed by the provider after its first message; the REST steps give a name, the window scenario renames through the API.
- To refresh a recording, run the same prompt once with `REEF_VERIFY_CLAUDE=record`, and tell claude to use no tools: its auto-memory otherwise tries a file Write or a Bash `cat` of its memory folder.
- The sidebar refreshes its Spaces every 5 seconds, so the window scenario waits for the order.
