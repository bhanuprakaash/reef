# Window

A user opens the Reef window in a browser at the address `reef serve` prints. They start a
Space on a Work item, chat and watch the agent's tool calls and text arrive live. A new
Space of the same Work item starts from the brief. A free Space can be attached to a
Work item, and a Space that hits a cap pauses and says why. A Space on a team names the running bot, opens replies in a Thread pane. Contract: `docs/server.md`
(Web UI, Spaces live, Wrap-up and attach, Caps).

## Sub-features

- `window-live` a claude Space on a Work item: a tool-using prompt shows tool rows while the turn runs; when it ends the reply is one stored `lead` message and the live view is gone.
- `window-brief` a new Space on a Work item whose brief exists answers the goal from that brief.
- `window-attach` a free Space attached to a work item from the header button and dialog: the free Space's turns, run in its own folder, have no checkpoint; the sidebar moves the Space under the work item; the Attach button is gone; the next turn runs in the worktree and has a checkpoint.
- `window-global` the All projects filter and chats without a Project: see `global-chats.md` (`$H ui global-chats`).
- `window-navigate` pins of a Bot, a chat and a Space (the row's More actions menu) survive a reload and sort to the top of their own sidebar section (a pinned older chat is the first Conversations row above a newer one), there is no Pinned section, Unpin removes one; the row menu's Rename changes the `space` row and Delete with confirm removes it, its row and leaves its page; a Bot pinned from its sidebar row menu sorts first; search finds a Bot, a chat, a Space and a Work item and a result opens it; a Bot with no chat opens its page with New chat and no chat is created; `PUT /spaces/{id}/coordinator` changes only the coordinator (`$H ui navigate`).
- `window-cap` a Space whose Work item's token budget is used shows a banner with the reason and a disabled composer, keeps it after a reload, and the next message runs after Continue.
- `window-pages` a bad project path shows the server's error; a work item can be added from the sidebar.
- `window-stop` Stop mid-turn shows `Failed: interrupted` and the partial reply once; the next message resumes the session.
- `window-wrap` Wrap up shows the proposal panel, Reject leaves the brief unchanged; `/wrap` then Approve makes brief version 1 and closes the Space: Wrapped and Reopen replace Wrap up and the composer, the Space is under Wrapped (1) in the sidebar. Reopen brings the composer back; Close Work item on the Work item page closes the item and its Space.
- `window-teams` the team picker makes a `duo` Space; the live turn names the lead, then the architect; a reply in the Thread pane is answered by the architect and the root shows `2 replies in thread`; in a `full` Space the lead hands off to the developer and the developer runs with no approval (the recipe is in `bots.md`).
- `window-retry` a failed turn shows a card with Retry; Retry runs the same wake as a new turn that ends `done`, and the row goes.
- `window-rollback` a Space with checkpointed turns lists them under Checkpoints, newest first, each with Roll back; Roll back asks to confirm, then the Work item's worktree has the same HEAD, `git status`, `git log` and files as before the turn, `reef` posts `Rolled back to before turn N.`, and the next turn's prompt starts with that note.
- `window-inbox` the Needs you row and `/inbox` list what waits on the user, live from `/inbox/events`: a new reply of a Space that is not open shows with Open and Dismiss on hover and fires one desktop notification; clicking an item, or its notification, opens its Space scrolled to and marking the item (the failed turn row, the pause banner or the newest message); an item of the Space open and visible fires no notification. `/inbox` groups its items under Needs you (paused, held, failed, review, question) and FYI (reply and the rest); a row is one line with the Bot's face, Space name, type label, cleaned preview and age, a Needs you row shows its one action (Retry, Continue, Review, Reply), a click opens the row to the rendered message, an unopened row has a dot and Dismiss all seen dismisses the opened FYI rows; only FYI rows have Dismiss, and the three FYI kinds of a Work item fire no notification.
- `window-diff` a Work item's review page (`/work-items/{id}/review`, reached from the diff side panel's expand button or the Work item page's header meta line) lists `GET /work-items/{id}/diff`: a turn that writes a file in the worktree, uncommitted, shows there as `A new.txt` with its added line.
- `window-memory` the project page (`/projects/{id}`, from the project switcher's Open project) lists the project's memory items (`GET /memory?scope=project:ID`), none for a new project; Add (kind and body) stores an accepted `project:ID` item with author `user`, it survives a reload, and Retire sets `retired_at` and drops it from the list. A Work item page lists the item's `work_item` memory items, one saved with `reef memory add` shows, and Retire there does the same. The page also has a Base branch field and a Purpose field, both saved when the field loses focus (no Save button): a name that is not a branch name is refused, `dev` is stored in `project.base_branch` and the Purpose in `project.purpose`, and both survive a reload. The memory list shows 3 items with Show all, and the memory rail stacks under the main column on a phone.
- `window-inspector` a Space's Inspector panel shows `GET /spaces/{id}/inspector`: totals (cost, tokens, turns) summed from the roles, one row per role that ran with its turn count, tokens and cost (`n/a` when the API has none) from the API, and every turn newest first; a developer turn expands to its prompt and a tool call with its name, input and result.
- `window-review` the review page lists files with A, M or D (a deleted file struck through, a file without hunks shows No text changes); clicking a line opens a comment box; drafts show under their line and are counted per file; Send to Developer posts them as one message, `path:line` per comment, to the developer's latest thread and clears the drafts.
- `window-workshop` the `/bots` panel edits a Bot's description, creature (`face`) and skills (a name not on disk shows as missing; a Codex Bot is offered every skill, `runtime-skill` (a `${CLAUDE_PLUGIN_ROOT}` in its file) is labelled "not usable here", and it has no tool picker) and saves them to the `bot` row (skills as `claude:` refs), its selected connections unchanged; the Bot panel shows the server's error for unrestricted `Bash` on a Bot without `write`, and picking allowed tools (checkboxes, a custom pattern field) saves them to the `bot` row; Settings lists the project's skills by source (Reef, Claude Code, Codex); Duplicate makes a new Crew; a new Space's developer session starts with the new description in its system prompt (the fake claude's log); a Bot edited after its session adopted shows the adopted settings in the Space's Bots panel with `Apply here to adopt edits`.
- `window-capture` the `/capture` window picks a project and takes a type, title and description; a successful capture shows "Captured", clears the text box and stores a Backlog Work item; with "Talk to a Bot" on, it opens a conversation whose first message is the text and stores no Work item; a failing request (a deleted project) shows its error.
- `window-first-run` the project step shows Choose… only with the desktop bridge, and choosing a folder fills the repo path.
- `window-pr` the Space header's `PR #N` chip opens a PR panel in the Space's side panel from `GET /work-items/{id}/pr` (title, number, state, base and head, review, each check with a passed, failed or pending icon, an external Open on GitHub link); Merge is disabled until gh calls the PR mergeable, Cancel in its confirm dialog merges nothing, confirming runs `gh pr merge 12 --merge` once and the panel shows Merged.
- `window-theme` Settings shows Appearance (Dark, Light, Match macOS) and Notifications; picking Light restyles the open page at once and survives a reload; Match macOS follows `prefers-color-scheme` (emulated over CDP) both ways; text on the Space, inbox and Work item page is at least 4.5:1 against its background in dark and light.
- `window-coordination` bots' direct messages show in the Space as one compact item (`Lead and architect are coordinating · N messages`) and never as bubbles; the item updates in place and says working, paused, failed, stopped or completed; it opens a Coordination panel that shows the running recipient's text growing live, then the full ordered exchange (sender, recipient, time, delivery status), a link to the public message it began from, and Continue or Retry for its state; it works at 1280x800 and 390x844 (`$H ui coordination`).
- `window-team` the team is a popover from the header Team button or the avatars, not a column: the Space keeps its width when it opens, Escape, an outside click and its X close it, and the header avatars ring the role that is working (no floating badge) (`$H ui team`, needs `full`).
- `window-denials` a bot's tool call that claude refused for lack of permission shows a card `<Role> was denied <tool>` with Add to role; Add stores the pattern in the role's `tools` (`GET /teams/{name}`) and the card says Added; the next wake of that role starts with it in `--allowedTools` and runs the tool; a read-only role refused `Write` shows `Needs write access`, a codex role `Codex ignores allowed tools`, neither has Add; the lead's Add also stops its agent so the next wake restarts it (`$H ui denials`).
- `window-subagent` a claude `Agent` call shows as a subagent row labelled from its input (`subagent_type` and `description`) with the subagent's own tool calls grouped under it: open while the call runs, collapsed once it is done (`sub-agent · N tools`); the Inspector shows the same group, collapsed, from `GET /spaces/{id}/inspector` (the `Agent` call's `children`), expandable to the nested calls; any other tool call and a codex turn show as before (`$H ui subagent`).
- `window-naming` a Space started with its name left empty shows a placeholder (`claude 02:32 PM`) with `name_auto` 1; after its first message the provider's one-shot name (`fix login redirect loop`) replaces it in `space.name`, the sidebar and the Space header, `name_auto` is 0, and the naming call leaves no turn or message; a failed proposal keeps the placeholder and the Space keeps working; a typed name and a rename sent right after the first message are never replaced (`$H ui naming`). The scenario `name-fail` has no recording on purpose: the fake claude answers it with an error; do not record it.
- `window-hovercard` hovering a Space row in the sidebar, or focusing it with the keyboard, shows a card after a short delay: the Space's name and state (idle, working, waiting for you, a failed turn, paused, wrapped), the Work item's branch `work-item/<id>` and its changes (files, `+added −removed`, from `GET /work-items/{id}/diff`), and every role of the team with its creature, `working` for each role in `GET /turns?status=running`. The card closes when the pointer leaves, on Escape, on a click and on navigation; moving onto it keeps it open; it is readable in light and dark; below 768 px it never shows.
- `window-mention` hovering an `@role` mention in a Space message, or focusing it with the keyboard, shows a card after a short delay when the role is in the Space's team: its creature, name, backend and model, the first line of its description, `Working` when the role is in `GET /turns?status=running` for the Space and `Idle` otherwise, `Can write` or `Read-only`, its tool count (claude roles), and an Edit link to `/teams?team=<team>&role=<role>`, which opens that team with the role's panel open. An `@word` that is not a role of the team is plain text with no card and no tab stop. The card closes when the pointer leaves, on Escape, on a click and on navigation; near the right edge it opens on the mention's left and stays inside the window; it is readable in light and dark; below 768 px it never shows.
- `window-sidebar` the sidebar lists Search, Inbox, Board, Bots, Spaces and Conversations top to bottom, then Bots and Settings at the foot, each linking to its page; a section shows at most 8 rows and a See all N link to its full list, and a collapsed section (chevron on its label) stays collapsed after a reload; each section's + (and the Board row's +) creates a Work item, a free Space and a conversation and opens each; a Work item's Space leaves the Spaces section when the item reaches Review; at 390x844 the Menu button opens the same sections as a sheet with no horizontal scroll (`$H ui sidebar`).
- `window-phone` below 768 px the sidebar is replaced by a bottom tab bar (Today, Board, Spaces, Needs you, Menu, which opens the sidebar as a sheet); each tab is one column with no horizontal scroll and 44 px tap targets, and widening past 768 px brings the sidebar back on the same page. At 390 px a Space hides the tab bar and has a Back link to `/spaces`; a thread opens as its own screen, the team and the inspector as bottom sheets, and the review page shows file chips and one full-width Send button.
- `window-board` `/board` shows the top-level work items in the columns Backlog, Queued, In progress, Needs you, Review, Done and Dropped, filtered by type, Team and project (the filters are in the URL). Dragging a queued card to Backlog moves it (`PATCH /work-items/{id}`); a Backlog card is queued by its Approve form; dropping a queued card on another card of the same Team changes its queue position (`PUT /work-items/{id}/queue-position`); a drop into any other column is refused with a message and nothing changes.
- `window-work-item-review` a top-level item in review shows a Review panel with the lead's wrap-up proposal next to the proof. Send back needs a note; with one, the item goes back to work and the lead's next prompt is `Sent back from review by the user:` and the note, and the proposal it waited on is rejected. One click on Done saves the proposal's memory items, approves it, closes the Space and sets `done`. A sub-item in review has no Review panel and no Done, and `PATCH {"status":"done"}` on it is 400.
- `window-space-header` a Space header names its kind. A Work item Space shows the item's title, status and budget used (REST `tokensUsed` over `tokenBudget`) and offers Open Work item; a free Space offers Attach to Work item and Add Bot; a conversation shows its Bot's creature and offers Add Bot. The Team panel lists `GET /spaces/{id}/members` with a creature each and a lead badge. Attach from the header makes the Space the item's Space (`ui space-header`).
- `window-work-item` `/work-items/{id}` shows the item's type and status, its acceptance lines and a sub-item added from the page as REST has them, the Team chip (set through `PUT /work-items/{id}`), the brief, and the proof read-only (Not submitted yet before a submit); a sub-item's page has no brief, sub-items or proof and links to its parent (`ui work-item`).
- `window-bot` `/bots/{id}`, from Open profile in the Bots panel, shows the Teams the Bot sits in with each Team's role and write access (REST), its description and model, its bot-scope memory, its conversations newest first; New chat opens a new one that REST lists first (Resume chat opens the latest); a Bot in no Team says so, and an unknown id shows an error (`ui bot`).
- `window-pending-memory` the Inbox lists candidate memory under Pending memory (kind, body, author Bot, scope, source Space); a replacement shows the item it would retire beside it; Approve accepts it and retires the old item with `replaced_by` set, Reject keeps the old item accepted, and the list leaves when empty (`$H ui pending-memory`).
- Each of `ui sidebar`, `board`, `work-item`, `work-item-review`, `space-header`, `bot` and `inbox-groups` runs its screen at 1280x800 and at 390x844 (no horizontal scroll) and saves a screenshot of each size.

Acceptance lines of the slice: "start a Space, chat, see streamed tool calls and text live" is
`window-live`; "a new Space of the same Work item starts from the brief" is `window-brief`;
"attach a free Space to a work item" is `window-attach`; "hitting a cap pauses the Space and shows why" is
`window-cap`. Not driven here: codex Spaces in the window and reload mid-turn (drive them by hand
in the browser).

## How to get to it (user POV)

- `cd web && npm ci && npm run build`, `go build -o reef ./cmd/reef`, `./reef serve`, open `http://127.0.0.1:7700`.
- Add a project, add a Work item, click New Space (or New free Space), type, Enter.

## Driving it with verify-reef

Preconditions:

- Baseline from the README, plus `node` and a Chrome: `/Applications/Google Chrome.app` on macOS; on Linux Playwright's Chromium with `REEF_VERIFY_CHROME` set (see `SKILL.md`, Window). Check it like `doctor` would: `"$REEF_VERIFY_CHROME" --version` prints a version. `error while loading shared libraries` means the system libraries are missing: `npx playwright@1.64.0 install-deps chromium`.
- The web app is built before `$H build`: `(cd web && npm ci && npm run build)`. The binary embeds `web/dist`; without it every page is 503 `UI not built`.
- The server starts with the model set, because it starts the `claude` agents: `ANTHROPIC_MODEL=sonnet REEF_VERIFY_RUN=<id> $H serve-start --data-name ui`.
- `ui teams` also needs the teams `duo` and `full` applied to the `ui` folder: `$H team-apply ...` after `serve-start --data-name ui` (files and commands in `bots.md`, Window).
- `ui inbox` needs `duo` too, and checks that a reply is FYI, so the Needs you badge stays absent, so it fails on a server that already lists needs-you items: run it first, or on its own folder (`serve-start --data-name inbox`, then `$H team-apply $E/duo.json`).
- `ui first-run` needs a server with no profile and no project: run it on its own folder (`serve-start --data-name first-run`).
- `ui team-management` needs the team `full` applied to the `ui` folder: `$H team-apply "$PWD/teams/full.json"` after `serve-start --data-name ui` (or `verify-reef one team-management full`).
- `ui inspector` needs the team `full` applied to the `ui` folder: `$H team-apply "$PWD/teams/full.json"` after `serve-start --data-name ui`.
- `ui review` needs the team `full` applied: `$H team-apply "$PWD/teams/full.json"` after `serve-start --data-name ui`.
- `ui theme` needs the team `duo` applied (like `ui inbox`) and leaves a reply for the inbox screen.
- `ui workshop` needs the team `full` applied: `$H team-apply "$PWD/teams/full.json"` after `serve-start --data-name ui`.
- `ui pr` needs a fake gh: serve-start with `REEF_FAKE_GH=<folder>`, `REEF_GH_INTERVAL=1s` and `scripts/ui/fake-gh` first on `PATH`, then `ui pr` with the same `REEF_FAKE_GH`; the fake keeps the PR in `<folder>/pr.json` and logs merges to `<folder>/merges.log`.
- `ui coordination` needs `duo` and `full` applied to the `ui` folder (the lead's direct request runs the architect at once).
- `ui subagent` commits a `sub.txt` to the run's folder (the Space runs in a worktree), asks the lead to read it through a subagent, and replays `fake/recordings/subagent-read.jsonl`, a real claude recording with `parent_tool_use_id` on the subagent's calls; it needs no team.
- `ui denials` applies its own team `denials` (a lead and a read-only reviewer, both allowed only `Read`) through `POST /bots` and `PUT /teams/denials`, and reads the fake claude's args from `fake-claude.log`, so it only runs on the fake `claude`.
- `ui hovercard` needs the team `full` applied: `$H team-apply "$PWD/teams/full.json"` after `serve-start --data-name ui`.
- `ui mention` needs the team `full` applied: `$H team-apply "$PWD/teams/full.json"` after `serve-start --data-name ui`.
- `ui phone` needs `duo` applied to the `ui` folder, and reads the Needs you badge as `1`, so run it first or on its own folder, like `ui inbox`.

Each scenario adds its own project through the form (`ui-<scenario>-<suffix>`, folder = the run's scratch cwd), so most run in any order on one server.
