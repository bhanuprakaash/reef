Visible embedding failures and rate limits

A write that could not store a vector says so, and a rate limit gets one retry.

Issue #38aa726c3219d2f5memory-servicebased on docs/restructure-proposal

What it does

Result.EmbedErr holds why no vector was stored (nil when stored or when no embedder is set). reef memory add prints vector not stored: <reason>; run reef memory embed <provider> to retry on stderr and exits 0. Vendor errors name the status and the vendor error code, such as status 429 RESOURCE_EXHAUSTED, never the message. A 429 waits for Retry-After (1 to 60 s) and retries once.

Why

Before, a failed embed was silent: the note lost meaning search and nobody knew. R30 records that the background pass waits for server wiring; until then the warning tells the user to re-run embed.
