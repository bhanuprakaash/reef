Reject a candidate

A candidate the user turns down becomes rejected and is never found again.

Issue #370afe99fmemory-servicebased on docs/restructure-proposal

What it does

New status rejected. Store.Reject works only on candidates; reef memory reject <id> calls it. Retire now works only on accepted notes. The memory tables get their own version table, memory_version, and ordered files under memory/migrations/. 002_rejected.sql rebuilds the memory table so its CHECK allows rejected.

Why

Before, rejecting meant retiring, and recall includes retired notes. So a rule the user refused showed up in recall as history. R18 keeps retired notes as what was believed; a rejected note never was.

Decisions made while building

Own version table, not user_version

store/ owns PRAGMA user_version. A db that has memory but no memory_version is at version 1.

A candidate cannot be replaced

Replace and retire take only accepted notes; a candidate is approved or rejected first.
