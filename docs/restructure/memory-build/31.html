Settings

Embedding settings

A setting table holds the embedding provider and key. One command turns meaning search on and fills the missing vectors.

Issue #314b4ff25f535a4cmemory-servicebased on docs/restructure-proposal

What it does

Store migration 34 adds setting (key, value). reef memory embed openai --key K saves embedding.provider and embedding.key. When embedding was off before, it runs Backfill once and prints how many items it embedded. reef memory embed prints the provider only. Every reef memory command builds its embedder from these two settings.

Why

Decision R20: one field turns on better search, and Reef stays free and local by default. No secrets table existed; MCP keys sit inside team role JSON.

How a request flows

reef memory embed openai --key K                         cmd/reef/memory.go
  check provider; reuse stored key only for the same provider
  prev := Setting(embedding.provider)                     store/setting.go
  SetSetting(provider), SetSetting(key)
  provider changed -> ClearVectors; not none -> Backfill -> "embedded N items"
reef memory add ...
  openMemory: Setting x2 -> memory.NewEmbedder -> memory.Open(db, e)

Decisions made while building

Test fake

The CLI test swaps http.DefaultClient.Transport, so no production hook exists only for tests.

Backfill error

The settings are saved first; a backfill error exits 1 with the vendor status, never the key.

Review fix: switching

The stored key is reused only for the same provider. A provider change clears every vector. Every embed <provider> that is not none runs Backfill, so a failed fill can be retried.
