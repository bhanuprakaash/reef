Write policy

Lookalike check on write

Remember tells the writer which stored items look like the new one. It never links them and never refuses the write.

Issue #2876cebf6memory-servicebased on docs/restructure-proposal

What it does

Before the insert, Remember embeds the text once. With a vector, every accepted item in the same scope with cosine at or above 0.92 is similar. Without a vector, the top word match is similar when it holds at least 70% of the new body's distinct words. The list comes back in Result.Similar as id and body. The same vector is stored with the item, so nothing is embedded twice.

Why

Decision R17: links come from the writer, and a lookalike check proposes but never links silently. The writer then decides to replace the old item or keep both.

Decisions made while building

Direct calls, not Recall

The check needs the raw cosine and the top word match. Recall's fused score has neither, so the check calls the vector scorer and Search directly.

Replaced ids

An id the note replaces is never reported; the writer already knows it.
