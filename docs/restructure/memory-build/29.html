Eval harness

Thirty scenarios in one JSON file score recall offline, and any forbidden item in a result fails the test.

Issue #2937d02caf8f1131memory-servicebased on docs/restructure-proposal

What it does

memory/eval/fixture.json holds the scenarios. Each one seeds items with symbolic names, asks one query with the asker's scopes, and names the expected and the forbidden items. TestRecall runs every scenario on a fresh in-memory database. It computes recall@10 (the share of expected items in the top 10) and MRR (one over the rank of the first expected item). It fails under the thresholds in the file. Synonym scenarios need meaning search, so they run only with -tags embed and a key in the env.

Why

Decision R26: deterministic checks cover write policy and scope isolation, which published benchmarks skip. Knowledge-update cases (replace, retire, conflict) are in the set.

How a request flows

go test -v ./memory/eval
  decode fixture.json (unknown fields rejected)
  per scenario: sql.Open(":memory:") -> memory.Open(db, embedder or nil)
    seed items in order (ref -> id), retire the ones marked
    Recall(Query{scopes, text, scope, limit})
    forbidden id in results -> FAIL now
    ordered and out of order -> FAIL now
    recall@10, MRR
  mean over scenarios that ran -> eval: line -> FAIL under thresholds
