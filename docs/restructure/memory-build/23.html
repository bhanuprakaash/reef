Memory tables and item writes

Package memory/ gets its own two tables and the calls that write, read, retire and accept one memory item.

Issue #2363a81b3memory-servicebased on docs/restructure-proposal

What it does

A memory item is one statement, for example Use sessions, not JWT. It has a kind, a scope, an author and role, and a status. Links point from the item to plain string targets. Remember writes the item and its links in one transaction. A note can name items it replaces; each replaced item becomes retired and points at the new item.

Why

Decisions R15 to R18 settle that memory is many small items, append-only, with links that are plain strings. The package owns its tables, so the store migration runner does not change. The caller passes the open database through a one-line DB() accessor.
