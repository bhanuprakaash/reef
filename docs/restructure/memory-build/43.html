Embedding settings

Embedding settings saved together and owner-only first

Provider and key are saved in one transaction, and reef.db is made owner-only before the key is written.

Issue #43d81c188memory-servicebased on docs/restructure-proposal

What it does

store.SetSettings writes several settings in one transaction and replaces SetSetting. memoryEmbedSet calls restrictDB before it, so the key never lands in a file others can read.

Why

Two separate writes could leave the new provider with the old vendor's key, which would then be sent to the wrong vendor. The chmod ran after the key was already in a 0644 file.

How a request flows

reef memory embed <p> --key K          cmd/reef/memory.go
  ClearVectors if provider changed     cmd/reef/memory.go:454
  restrictDB (0600)                    cmd/reef/memory.go:464
  SetSettings{provider, key} one tx    store/setting.go:25
  Backfill
