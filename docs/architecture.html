Five rules that explain everything

  1. Agents are processes. Every teammate is a real claude or codex CLI that reef serve launches headless. Reef never calls a model API itself. Adapters turn each CLI's output into one agent.Event type.
  2. SQLite is the source of truth. reef serve, reef mcp, reef chat and the CLI all open reef.db directly. Only the live chain (hop count, queued wakes, SSE frames) lives in memory.
  3. Routing is plain code, at turn boundaries. When a turn ends, space.Route applies four @mention rules to what that role wrote. No model picks the next speaker, and nobody is interrupted.
  4. Memory is read once, then pulled. A new session gets one prompt: brief + memory items by scope (every live decision, the newest of the rest, each with a count) + sub-items in progress. Anything deeper comes through reef mcp tools on demand.
  5. You approve the brief and the wrap-up. Briefs and wrap-ups are proposals that wait for you. Memory items an agent saves with remember are written at once, except a convention from a role other than architect or lead, which waits as a candidate. Only you set a Work item done.

4Private direct chains: send_to_role

One request, one automatic response, and then it stops. Continuing needs another explicit send. That single rule is what prevents two agents from ping-ponging forever.

Who can see it

readersees
Youall of it
Sender, recipient (MCP)their own
Other rolesnothing
read_thread, message listnever
Wrap-up turnall, as [direct 1] a -> b: …

When it fails

  • Recipient turn fails: a failed response is stored, so the sender can tell. It does not wake the sender.
  • Your message drops a held wake after a hop-cap pause: a failed response with body dropped.
  • You press Stop with a wake queued: failed response stopped.
  • Retry appends the one done response; a unique index allows only one.

How private work reaches the team

Not through search. The sender publishes one concise outcome with post_to_space, or it lands in the brief and memory items at wrap-up, which reads every direct exchange of the space.

A new Space never gets direct messages in its context.

5The wake loop: how a Space wakes teammates

When a turn ends, chain.runTurn decides what runs next. Everything on this page is plain Go in server/live.go, server/wake.go and space/route.go.

Turn ends
The role's reply is now a message row, the turn is done.
wakes() + directWakes()
Read messages stored after the cursor, written by the role that just ran (its reply and any post_to_space). Read its new direct_message rows.
space.Route
Thread owner, @mentions, lead, or nobody. Build the header. Merge same-role same-thread wakes.
Queue
Open wakes are appended. A message you send mid-chain joins l.queued and runs after the current turn.
checkSpace + countHop
Closed? Paused? Over the token budget? A turn woken by an agent counts a hop, and a turn that called a tool other than Reef's own resets the count; the 7th does not run.
Pause + hold
space.paused = reason, wakes stored as approval kind hold. Continue, or your next message after a hop pause, runs or clears them.
runOne → Session.RunAs
Publishes turn: running and runs the role. Strictly one turn at a time per space.
Chain ends
Nothing left to wake, a failed turn, a stop or a pause. The Space goes idle.

The four routing rules

func Route(m store.Message, owner string,
	roles []string, lead string) []string {
	// 1. user reply in a thread → thread owner (lead if user owns it)
	if m.ParentID != nil && m.Author == "user" { ... }
	// 2. every @name that is a role of the team, once each;
	//    the sender and unknown names are skipped
	_mention = regexp.MustCompile(`\B@([\w-]+)`)
	// 3. otherwise a message from the user → the lead
	// 4. otherwise nobody
}

A role never wakes itself. An agent message that names nobody wakes nobody, so the lead does not answer every specialist post.

The wake text

[Space 5, message 12]
[Space 5, message 12, thread 9]
Thread so far:
user: can we add SSO?
architect: not in v1...

reef wrote: Rolled back to before turn 7.
lead wrote: @architect design the form
Asked together: @architect, @tester

Your text goes in as typed. An agent's goes in as <author> wrote: <body>. A private wake starts [Space N, direct message N, chain N, source: direct request].

Caps

capdefault
talk-only agent hops6 per user message
token budget1,000,000 per top-level Work item
tool calls per turnnone

There are no approval gates: Review with proof checks the result. A hop is a turn an agent's message woke; a turn that calls any tool other than Reef's own resets the count, and so does your message. The budget counts input + output + cache-write tokens, cache reads do not count, and is checked between turns. A pause moves the Work item to Needs you.

Who stays alive

  • The lead's agent stays open until the Space stops.
  • A specialist's agent is interrupted and its token deleted when its turn ends. Its next wake resumes the same session id.
  • A role with write waits for the tree's write lock. Read-only roles run beside it.

Example chain

  1. You → lead (rule 3).
  2. Lead replies @architect design the form (rule 2).
  3. Architect runs, posts a plan naming nobody (rule 4).
  4. Chain ends. The lead gets no turn after the plan.

If the architect said @developer build it, the developer would run next and the chain would count one more hop.

When a chain also runs from elsewhere

  • Queue: a free Team's first queued Work item starts, and its lead gets the item as a message.
  • Retry a failed turn: runs its stored wakeText as if you had sent it; resets hops.
  • Failed CI: author reef wakes the developer; it counts as a hop.
  • Continue: runs the held wakes as a new chain.
The wake loop

6One SQLite file, many processes

There is no queue and no RPC between Reef's processes. They coordinate through reef.db (WAL mode, 5 second busy timeout) and a few file locks.

Who opens it

processcountlock
reef serve1 per data folderreef.lock for as long as it runs
reef mcp1 per awake teammatenone; stops when stdin closes
reef chat1 per open terminal spacechat-<space id>.lock
CLI commandone-shotnone

A Space run by reef serve also holds its chat-<id>.lock, so reef chat --space ID fails with space 1 is open elsewhere.

Append-only where it matters

  • Messages and memory items: create and read only. An item can be retired (retired_at, replaced_by), never edited or deleted.
  • Brief: every change adds a version. Old versions stay.
  • Turns: created running, ended once as done or failed. A failed one can be marked retried once.
  • Work item status changes only through MoveWorkItem, which checks who may make each move.
  • Deleting a Work item closes the memory items of its scope: they are retired or rejected, and still read.

First turn vs every later turn

  1. member() looks for the role's newest turn with a session id, in this Space, on this backend.
  2. None → startPrompt() becomes the Runner's preamble. The first Send is preamble + "\n\n" + wake text, then the preamble is cleared.
  3. Found → ag.Resume(cfg, sessionID). The first prompt is not sent again, unless the backend compacted the session.
  4. Small deltas on a resume: ### Changed since your last turn lists the memory items accepted or retired since, and ### New brief the brief when a newer version exists; a changed persona or skills goes in front marked Your persona or skills changed:; and withNotes adds reef wrote: … lines (a rollback note, a restart note) right after the wake header.
  5. Across Spaces sessions are never shared. A teammate's memory of other Spaces is the brief, memory items and the tools.

Free Space (no Work item)

A team is a roster of Teammates: a JSON file applied with reef team apply, or built in the window from existing Teammates. A Space copies its members from the team. The role's write flag becomes each backend's own limit in access().

10What happens when…

The guard rails are code, and each failure has a defined result.

eventwhat Reef does
The server restarts mid-turnAt start, every turn still running becomes failed: server restarted and the Space gets a note: "The worktree may be dirty; retry or roll back." Held wakes survive. The hop count does not. A failed turn keeps its wake, so Retry works.
You press StopThe running turn is stored failed: interrupted, waiting wakes are dropped, every agent of the Space stops and its token is deleted. The chat lock is released.
The 7th talk-only agent hopIt does not run. The Space pauses with hop cap: 6 agent hops without a user message, its Work item moves to Needs you, the wakes are stored as holds and an inbox item appears. Your next message clears the pause and drops the holds.
Token budget usedThe Space pauses with token budget of 1000000 used. Continue sets the Work item's budget to tokens used + 1,000,000 and runs the holds.
Two write turns on one treeThe second waits for the flock, polling every 20ms, across Spaces and processes. Read-only roles are not held.
Checkpoint failsThe turn is stored failed with git's error and the agent never gets the prompt.
You roll back a turnFiles and branch go back to the checkpoint. 409 if any turn runs on the tree. The agent's session is not rewound, so Reef posts Rolled back to before turn N. and the next prompt carries it as a reef wrote: line.
The agent process exits mid-turnThe turn is failed: agent exited with the reply streamed so far kept. The session closes; the next turn resumes by session id.
The database fails while routingThe Space pauses with the error as its reason and nothing more runs.
reef chat and the server want one spaceWhoever holds chat-<id>.lock wins; the other gets 409 open elsewhere.
CI fails on the Work item's PRThe poll posts a note as author reef and wakes the developer with the failing runs and the last 50 log lines. It counts as a hop.
The Mac app is not openAll browser tools fail with browser unavailable: the Reef app is not open. Everything else works.
You press Take overEvery browser tool fails with the user has the browser until Hand back.

11The Mac app, the browser and releases

Electron is a shell. The only desktop-only pieces are the browser pane, the terminal and the updater.

Start up

  1. Read PATH from your login shell.
  2. Spawn reef serve --addr 127.0.0.1:7700 --data …. The dev copy uses 7701 and its own data folder.
  3. Show the splash. When the server logs listening on, load http://127.0.0.1:7700.
  4. If the child exits, show its last 64 KB of stderr and quit. Never trust another process on the port.

The browser tools

An agent calls browser_snapshot, gets refs like e12, then browser_click. The call goes reef mcp → browser.sock → the app, not through reef serve.

Releases and updates

  • Every merge to main that passes tests is a release v0.1.N.
  • The app asks GitLab for the latest release every 60 minutes and downloads Reef-mac-arm64.zip.
  • A helper that outlives the app swaps the bundle, keeping the old version and a copy of the database, so a bad update rolls back.
  • REEF_SOURCE=github switches the source.
